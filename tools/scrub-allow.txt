# Known-OK lines for tools/scrub-scan.mjs (B3.0, B6.1): "<path> <pattern> <id>" per line.
#   path     the path the scanner prints; * matches within a folder, ** across folders,
#            and **/ also matches no folder.
#            A commit or tag hit's path is "commit" or "tag".
#   pattern  a pattern name (node tools/scrub-scan.mjs --list), or * for any.
#            "unscanned" entries let --strict pass a file the scanner can't read.
#   id       the id printed with the hit, or * for every line of that path. Use * rarely.
#            The id is HMAC-SHA256 of the trimmed line keyed by the private terms file's
#            id-key (first 12 hex), so it names no line to anyone without that key. A new
#            id-key changes every id: rerun the scan and update the entries.
# An entry stops matching when its line changes, so a changed line is reviewed again.
# Only paths, pattern names and ids go here, never the values themselves.

# ships, and each Authenticode signature carries the certificate, whose subject is the signer's
# legal name. That's public by design (Windows shows it as the publisher), and it can't be left out
# of a signed build. Its two lines (the ids) are all the signed build of 2026-10-02 (release run
# 37050891739, attempt 2) found in the binaries: the exe, the DLLs, the helpers, the keyring addon and
# the installer. The scanner reads a PE's certificate table as text whatever its entropy (code health
# EX-06 / signature regions), so both ids are expected in every signed PE and Setup, each twice
# (+0x74C and +0x762 in the table, again at +0xDE7 and +0xDFD): 1.4.1's 11 signed PEs show 44 lines,
# these two ids and nothing else. Before, the entropy gate's 4 KB blocks (AP-06) decided per build.
